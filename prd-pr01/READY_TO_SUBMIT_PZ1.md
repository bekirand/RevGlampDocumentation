# Практическое занятие №1 (ПЗ-1): Готовые бланки для сдачи

> **Тема проекта:** Разработка сервиса динамического ценообразования для малых средств размещения (загородные отели, глэмпинги, базы отдыха) — **«RevGlamp»**  
> **Группа:** ЭФБО-17-25  
> **Руководитель проекта (Project Manager):** Белишко Кирилл  

---

## Бланк А. Стартовые ответы по выбранной теме

| № | Вопрос | Ответ команды |
| :-: | :--- | :--- |
| **1** | **Что вы хотите сделать?** | Разработать веб-сервис динамического ценообразования (Dynamic Pricing Engine) для малых средств размещения (загородные базы отдыха, глэмпинги на 10–35 номеров). Сервис автоматически рассчитывает и рекомендует оптимальные посуточные тарифы на 30–60 дней вперед, анализируя текущий темп бронирования, глубину дат до заезда, открытый прогноз погоды и праздничные дни. |
| **2** | **Для кого вы это делаете? Назовите конкретных людей, а не категорию** | Для управляющих малых загородных средств размещения (целевой профиль/архетип: управляющий загородным глэмпинг-клубом / эко-отелем на 10–25 домиков в Московской или Тверской области). Профиль и типовые регламенты сформированы на базе открытых исследований **Ассоциации глэмпингов России (АСГ)** и кейсов профильных изданий (*Frontdesk.ru*, *vc.ru*, блог *Bnovo*). Это специалист, который лично формирует сетку тарифов, не имея в штате выделенного аналитика по ценам. |
| **3** | **По какому признаку вы поймёте, что работа закончена?** | 1. Развернут работающий сервис с веб-интерфейсом календаря тарифов.<br>2. Алгоритмический движок рассчитывает тарифную сетку на 60 дней вперед менее чем за 1.0 с.<br>3. Система успешно загружает открытый прогноз погоды (Open-Meteo) и производственный календарь, динамически меняя цены в зависимости от загрузки и дня недели.<br>4. Отельер может в 1 клик принять рекомендацию и экспортировать обновленные цены в CSV или по ссылке iCal для своей шахматки бронирования.<br>5. Тестирование на подготовленном датасете показывает прирост расчетной метрики RevPAR (выручки на доступный номер) не менее чем на 12%. |

## Бланк В. Сравнение вариантов темы проекта

| Критерий | Вариант 1 (Выбранный) | Вариант 2 (Отклоненный) | Вариант 3 (Отклоненный) |
| :--- | :--- | :--- | :--- |
| **Формулировка темы** | Сервис динамического ценообразования для малых средств размещения (RevGlamp) | Сервис бронирования проектных пространств и коворкингов университета | Telegram-бот расписания занятий и уведомлений для учебной группы |
| **Кто конкретно столкнулся с этой задачей** | Управляющие загородных глэмпингов и баз отдыха (10–30 номеров), теряющие выручку при плоских тарифах | Студенческие команды, ищущие свободную аудиторию перед дедлайнами | Студенты потока, проверяющие изменения расписания в дни сессии |
| **Кто будет заказчиком результата** | Собственник или управляющий малого средства размещения (целевой профиль на основе рынка) | Руководитель студенческого коворкинга / администрация корпуса | Староста группы / студенческий совет |
| **Реально ли сделать за один семестр (да / нет, почему)** | **Да:** базовый движок эластичности на правилах + погодный API + календарь реализуются в 1 семестре, а во 2 семестре масштабируются в ML и аналитику | **Нет:** высокий риск упереться в бюрократическое согласование регламентов доступа и ключей от аудиторий с охраной | **Да:** задача слишком простая, будет завершена за пару недель, объема не хватит на семестр |
| **Чем будет измерен результат** | Рост расчетного RevPAR ($\ge 12\%$), время расчета цен ($p95 \le 1.0$ с), работающий веб-календарь с экспортом цен | Число бронирований слотов, отсутствие коллизий двойной брони | Количество активных пользователей бота в день |
| **Что может помешать** | Сложность получения реальных закрытых данных отелей (полностью снимается синтетическим генератором и открытыми выборками) | Отказ комендантов пускать студентов по электронным броням без бумажных служебных записок | Наличие уже работающих официальных ботов университета и API-ограничения |

### Обоснование выбора Варианта №1:
> Тема №1 имеет прямую экономическую ценность для реального сектора бизнеса, не имеет организационных барьеров доступа к закрытой инфраструктуре, позволяет задействовать сильные стороны всех 5 участников (управление проектом, бизнес-анализ, веб-разработка, анализ данных) и органично разделяется на рабочий MVP в 1-м семестре и масштабный аналитический продукт во 2-м семестре.

## Бланк Д. Критерии и мини-матрица сравнения

| Группа критериев | Критерий команды |
| :--- | :--- |
| **Функциональность** | Автоматический учет локального прогноза погоды и календаря праздников при расчете тарифа. |
| **Пользовательский сценарий** | Возможность подтвердить или скорректировать рекомендованный тариф на месяц в один клик. |
| **Данные / интеграции** | Экспорт готовой сетки тарифов по стандартной ссылке iCal / CSV без необходимости сложной API-интеграции. |
| **Качество системы** | Гарантированное соблюдение порогов цены (*Floor/Ceiling*): цена никогда не упадет ниже себестоимости. |
| **Ограничения и риски** | Доступность для малого бизнеса: работа без покупки дорогой enterprise-подписки и без штатного аналитика. |
| **Ценность для пользователя** | Измеримый прирост дохода на доступный номер (RevPAR) за счет ликвидации просадок в плохую погоду и допродажи в пики. |
| **Дополнительный критерий команды** | Скорость генерации рекомендаций: полный пересчет цен на 60 дней вперед менее чем за 1 секунду. |

### Три вопроса для экспертной проверки в профессиональных сообществах отельеров (Telegram-чаты управляющих глэмпингами / открытые опросы):
1. *«Как вы сейчас определяете, какую цену выставить на следующие выходные, если прогноз погоды резко меняется с дождя на жару?»*
2. *«Сколько времени в неделю у вас сейчас уходит на просмотр цен соседних баз отдыха и ручное изменение тарифов в шахматке?»*
3. *«Случались ли за прошлый сезон ситуации, когда из-за плоского тарифа все домики раскупались за месяц вперед по низкой цене, а в дни заезда на них был ажиотажный спрос?»*
