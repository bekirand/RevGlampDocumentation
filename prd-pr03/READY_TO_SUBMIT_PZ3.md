## 1. Памятка и правила составления Use Case

| Правило | Проверка |
| :--- | :--- |
| **Актор — роль, а не человек и не должность** | Для человека: есть цель? Для внешней системы: какой сервис даёт или получает? |
| **Название — глагол + объект на уровне пользователя** | «Загрузить брони», «Утвердить тарифы», а не «Открыть окно» и не «Алгоритм». |
| **Основной актор у Use Case только один** | Тот, чью цель система удовлетворяет в данном прецеденте. |
| **Соответствие контекстной диаграмме C4 (ПЗ №4)** | Каждый прецедент отражен в связях диаграммы контекста системы. |

## Бланк 4. Ключевой Use Case №1

### UC5: Просмотреть рекомендации и утвердить тарифную сетку в веб-календаре
* **Основной актор:** Управляющий объектом.
* **Заинтересованные стороны:** Управляющий — быстрое утверждение цен; Собственник — соблюдение Floor Price; Гость — прозрачный тариф.
* **Предусловие:** Загружена история броней (UC1), задан Floor Price (UC2) и рассчитаны рекомендации (UC4).
* **Триггер:** Управляющий открывает рабочий веб-календарь для еженедельной проверки тарифов.

| № шага | Кто действует | Что происходит (намерение, без привязки к интерфейсу) |
| :-: | :--- | :--- |
| **1** | Управляющий | Запрашивает отображение календаря тарифов на выбранный период (30–60 дней). |
| **2** | Система | Отображает посуточную сетку с рекомендованными ценами, статусом спроса и прогнозом погоды. |
| **3** | Управляющий | Выбирает интересующую дату для детального просмотра обоснования тарифа. |
| **4** | Система | Показывает декомпозицию цены (базовый тариф + надбавка за темп бронирования + погодный коэффициент). |
| **5** | Управляющий | Корректирует значение цены вручную или оставляет рекомендованное системой. |
| **6** | Система | Проверяет валидность введенного значения (цена $\ge$ Floor Price). |
| **7** | Управляющий | Подтверждает утверждение тарифов на весь выбранный период. |
| **8** | Система | Фиксирует утвержденные тарифы в базе данных и обновляет постоянную iCal-ссылку. |

* **Постусловие (успех):** Тарифы на период сохранены в статусе «Утверждено», сформирован актуальный экспортный поток для PMS.  
* **Гарантированный результат (неуспех):** При отмене или сбое сохраняются ранее утвержденные тарифы, несогласованные правки не применяются.

## Бланк 5. Ключевой Use Case №2

### UC6: Экспортировать утвержденные тарифы в формате iCal/CSV
* **Основной актор:** Система управления отелем (PMS) / Управляющий объектом.
* **Вспомогательный актор:** Внешняя шахматка отеля (Bnovo / TravelLine / RealtyCalendar).
* **Предусловие:** Сетка тарифов на запрашиваемый период утверждена управляющим (UC5 завершен успешно).
* **Триггер:** Периодический HTTP GET запрос от внешней шахматки по URL либо клик управляющего «Скачать CSV».

| № шага | Кто действует | Что происходит |
| :-: | :--- | :--- |
| **1** | PMS / Управляющий | Запрашивает экспорт тарифов в выбранном формате (обращение по URL iCal либо скачивание CSV). |
| **2** | Система | Проверяет наличие утвержденных тарифов для запрашиваемого объекта. |
| **3** | Система | Формирует поток данных по стандарту RFC 5545 (iCal) или структурированный CSV со столбцами дат и цен. |
| **4** | Система | Передает сформированный файл клиенту со статусом HTTP 200 OK и корректным MIME-типом. |
| **5** | Внешняя PMS | Импортирует тарифы в свою шахматку бронирований без ошибок парсинга. |

* **Постусловие (успех):** Актуальные утвержденные тарифы успешно переданы во внешнюю шахматку без ручного ввода.  
* **Гарантированный результат (неуспех):** В случае ошибки генерации внешняя PMS получает HTTP 500 и продолжает использовать предыдущий кэш.

## Бланк 6. Альтернативные и исключительные потоки

| Use Case, шаг | Условие отклонения | Что делает система | Чем заканчивается |
| :--- | :--- | :--- | :--- |
| **UC5, 5а** | Управляющий вводит цену ниже установленного Floor Price | Блокирует сохранение, подсвечивает поле красным и выводит предупреждение о нарушении себестоимости | Возврат к шагу 4, цена удерживается на уровне Floor Price |
| **UC3, 2а** | Внешний сервис Open-Meteo API не отвечает (> 2.0 с) или вернул ошибку 5xx | Применяет нейтральный погодный коэффициент (1.0), выводит предупреждение: «Погода недоступна, расчет по базовой модели» | Расчет завершается успешно с пометкой в интерфейсе |
| **UC1, 2а** | Загружаемый CSV-файл истории броней поврежден или не содержит обязательных колонок | Прерывает импорт, формирует отчет с указанием номеров ошибочных строк | Возврат к окну загрузки, старые данные не повреждены |
| **UC6, 2а** | Запрос экспорта поступил для периода, где тарифы еще не утверждены | Генерирует экспорт с пометкой «Предварительный» либо уведомляет о необходимости утверждения | Управляющий перенаправляется на шаг утверждения цен в календаре |

## Бланк 7. Пользовательский сценарий (раскадровка экранов)

1. **Экран 1. Параметры объекта:** Ввод категорий жилья, базового тарифа и Floor Price (UC2) $\rightarrow$ Кнопка «К календарю» $\rightarrow$ Экран 2.
2. **Экран 2. Интерактивный веб-календарь:** Сетка на 60 дней: даты, рекомендованные цены, цветовой индикатор спроса, погода (UC3, UC4, UC5) $\rightarrow$ Клик по ячейке даты $\rightarrow$ Экран 3; «Утвердить» $\rightarrow$ Экран 5.
3. **Экран 3. Модальная карточка даты:** Декомпозиция тарифа (база, спрос, погода), поле ручной правки $\rightarrow$ «Применить» $\rightarrow$ Экран 2 (при ошибке $\rightarrow$ Экран 4).
4. **Экран 4. Ошибка валидации:** Модальное окно: «Ошибка: цена ниже защитного порога Floor Price» $\rightarrow$ «Исправить» $\rightarrow$ Экран 3.
5. **Экран 5. Окно подтверждения:** Сводка измененных дат, средняя цена, прогнозируемый RevPAR (+14%) $\rightarrow$ «Подтвердить и утвердить» $\rightarrow$ Экран 6.
6. **Экран 6. Экспорт iCal/CSV:** Постоянная ссылка iCal для шахматки PMS (UC6) + кнопка скачивания CSV $\rightarrow$ Завершение сценария.

## Бланк 8. Проверяемые требования к качеству

| № | Требование в проверяемой форме | Как проверить | Use Case и шаг | Откуда значение |
| :-: | :--- | :--- | :--- | :--- |
| **1** | При 50 одновременных управляющих расчет рекомендаций на 60 дней выдается не дольше 1.0 с ($p95 \le 1.0$ с, ошибок $\le 0.1\%$) | Нагрузочный тест (Locust / k6) | UC4, шаг 2 | Требование Лекции №2 к интерактивным сервисам |
| **2** | 100% сгенерированных и утвержденных тарифов удовлетворяют условию $Price \ge Floor\_Price$ | Автоматический тест на 500 итераций | UC5, шаг 6 | Финансовое требование заказчика (защита себестоимости) |
| **3** | Доступность iCal-эндпоинта составляет не менее 99.5% времени за месяц | Uptime-мониторинг | UC6, шаг 4 | Стандарт надежности интеграций с шахматками |
| **4** | Утверждение тарифов на месяц выполняется за $\le 3$ минуты и не более чем за 3 клика | Юзабилити-тест на 5 респондентах | UC5, полный сценарий | Цель продукта из Бланка 6 (ПЗ №2) |
